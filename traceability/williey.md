## Requirement changes

| ID | Original requirement (P3) | Revised requirement | Why it changed |
|---|---|---|---|
| R1 | Read-aloud speaks the reply from its first word to its last, in order, without stopping early or skipping, repeating, or adding words from the TTS message which may be different from the display message. (Acceptance: a 2,000-word, ~10,892-byte reply "should send 3 requests to the TTS in the right order".) | Read-aloud sends the whole reply to the voice in order: the speakable text is split into requests that each fit the speech service's 4,096-byte limit and that, joined back together, give the text exactly, with no word skipped, repeated, added, reordered, or (if it is 400 characters or shorter) cut between two requests. Reading only stops before the last word if the user stops it or the speech service fails. | **Feasibility and checkability.** "Without stopping early" can't be promised: the Edge voice service can drop the connection mid-reply, and running `/speech` again stops reading on purpose. "Send 3 requests" can't hold for every reply of that size: requests are cut only at sentence ends, so the count depends on where sentences fall (four 2.1 KB sentences, 8.4 KB in all, need 4 requests, not 3). What interviewees needed (O-5, C-3: every word, in order, nothing skipped, repeated or added) is kept and made checkable: the requests must join back into the exact text. |
| R2 | The text sent to the voice should match the reply word for word, except for intentional rewrites, fixes, or substitutions. (Acceptance: `speakable("See the [setup guide] (https://example.com/setup) or https://example.com/faq first")` "should return see the setup guide or the example link first".) | The text sent to the voice keeps every word of the reply, unchanged and in order. The only changes allowed are: a link or image is read as its label, a bare URL is read as "link", a fenced code block becomes "Code block omitted.", markdown formatting, HTML tags and emoji are dropped, and each line ends with punctuation. Inline code is read exactly as written. Nothing is autocorrected. | **Checkability, and a conflict between interviewees.** "Except for intentional rewrites, fixes, or substitutions" never says which changes are allowed, so no output could fail it; the revision lists them. "Fixes" came from C-12/C-15 (autocorrect words that look similar), which conflicts with O-11, O-12 and C-14, who count any changed or skipped word as a mistake; word for word wins and autocorrect is dropped. The P3 example was also wrong: its link had a space between `]` and `(`, so it isn't a markdown link, and it expected "the example link", which the design never says (bare URLs are read as "link"). |
| R4 | The voice should never say punctuation or markdown symbols as words and should just be a simple pause. | The text sent to the voice never contains markdown formatting symbols (heading `#`, list bullets, `*` `_` `~~` emphasis, backticks, `>` quote markers, `\|` table pipes, or link brackets) outside inline code. Sentence punctuation (. , ! ? : ;) is kept, so the voice pauses on it instead of saying it. | **Checkability, and a conflict with R2.** What the neural voice says out loud can't be observed in a test, and sentence punctuation has to stay in the text for the voice to pause on it (C-11, O-9), so the requirement is restated in terms of the text we send. It also conflicted with R2: inline code such as `**kwargs` must keep its symbols to be read word for word, so the rule applies outside inline code. |
