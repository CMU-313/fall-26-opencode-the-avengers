## Requirement changes

| ID | Original requirement (P3) | Revised requirement | Why it changed |
|---|---|---|---|
| R1 | Read-aloud speaks the reply from its first word to its last, in order, without stopping early or skipping, repeating, or adding words from the TTS message which may be different from the display message. | Read-aloud should read the whole reply in order. The text is split into requests that are each 4,096 bytes or less, and joining them back together should give the same text, so no words get skipped, repeated, added, or cut in half (unless one "word" is over 400 characters, like a long hash). It only stops early if the user stops it or the speech service fails. | Feasibility and checkability. We can't promise it never stops early since the Edge service can drop in the middle of a reply, and running /speech again stops it on purpose. Also my P3 example said it "should send 3 requests", but that isn't always true because we only split at the end of sentences, so four 2.1 KB sentences (8.4 KB total) need 4 requests. I kept what O-5 and C-3 wanted (every word, in order) but made it something we can actually check. |
| R2 | The text sent to the voice should match the reply word for word, except for intentional rewrites, fixes, or substitutions. | The text sent to the voice should keep every word of the reply in the same order. The only changes allowed are: links and images are read as their label, bare URLs are read as "link", code blocks become "Code block omitted.", markdown, HTML tags and emoji get removed, and each line ends with punctuation. Inline code is read as it is, and there is no autocorrect. | Checkability and a conflict. "Intentional rewrites, fixes, or substitutions" was too vague to test, so now it lists the exact changes. The "fixes" part came from C-12 and C-15 (autocorrect), but that conflicts with O-11, O-12 and C-14, who said a changed or skipped word is a mistake, so I dropped autocorrect. My P3 example was also wrong: the link had a space between `]` and `(` so it isn't actually a link, and the TTS says "link", not "the example link". |
| R4 | The voice should never say punctuation or markdown symbols as words and should just be a simple pause. | The text sent to the voice should never have markdown symbols in it (`#`, list bullets, `*`, `_`, `~~`, backticks, `>` or `\|`) unless they're inside inline code. Normal punctuation like . , ! ? : ; stays so the voice pauses on it instead of saying it. | Checkability and a conflict with R2. We can't test what the voice actually says out loud, and punctuation has to stay so the voice pauses (C-11, O-9), so I changed it to be about the text we send. Also inline code like `**kwargs` needs to keep its symbols to be read word for word (R2), so the rule only applies outside inline code. |
